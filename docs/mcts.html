摘　要

本篇描述 ZenZero 的树搜索层。它面对的工程矛盾只有一个：AlphaZero 式搜索每步要做数百次网络评估， 而 GPU 只有在一次收到几十上百个局面时才高效。我们沿两条正交路线解决它——用虚拟损失（第 5 节）使 同一手棋内的 K 条搜索线互不踩踏、并发提交；用无屏障流水线（第 6 节）使请求流在时间上连续、 引擎任何时刻都有可凑的批。两者都保持与串行搜索的语义一致性（5.3 节的论证与附录测试）。 实测搜索请求吞吐 5.8k → 62.9k 局面/秒（10.8×）；同等搜索预算下，自博弈从 6.7 局/分提升到 95.4 局/分（第 9 节）。

1　引言：搜索为什么是瓶颈

AlphaZero 闭环 [1] 的三层结构里（对局规则 → §1 篇，决策 → 本篇，算力 → §3 篇）， MCTS（Monte Carlo Tree Search，蒙特卡洛树搜索）负责把"网络的直觉"放大成"经过计算的决策"： 对当前局面做数百至数千次推演；每次推演沿树下降到一个未评估的叶子，请神经网络给出该叶子的 先验策略与局面评估，再把结果回填到路径上。最终决策取访问数分布 π（7.1 节）。

这个循环有两个天然属性，共同决定了它在工程上是瓶颈：

  • 串行依赖：一次推演的下降路径依赖此前所有推演的统计量——天真实现里"问网络 → 回填 → 再下降" 必须顺序执行，GPU 每时刻只收到 1 个局面；
  • 高固定成本：GPU 一次前向的开销大头是固定的（§3 篇式 (1)），单局面入批与 256 局面入批的 耗时差不到一倍，摊到每个局面的成本却差十几倍。

因此本篇的全部内容可以概括为一句话：在不改变搜索语义的前提下，把"一次一问"重排成 "多问并行、随到随批"。手段是虚拟损失（空间维并行）与流水线（时间维连续）。

3　PUCT：带先验的上置信树

下降每一步在节点 s 上选使下式最大的合法动作（UCT 加上网络先验项的变体， 形式取自 AlphaZero [1]）：

U(s,a) = W(s,a) + cpuct · P(s,a) · N(s) 1 + N(s,a) 　,　a ∈ A(s)

分子第一项是累计回报（越大越该走），第二项是"先验 × 尚未充分探索"的鼓励；分母使重复选择同一边的 边际收益递减。没走过的边（N=0）只要 P 不为零就有机会被试。

两处实现细节（与伪码等价，但值得写明）：
① 常见伪码把 argmax 对象写成"均值 Q̂ + 探索项"；本实现把两项并入同一分式后一次 argmax(child_scores)——把 Q̂≡W/(1+N) 通分回同一分母后，两式恒等； 好处是每节点只存 W/N/P 三张定长数组，均值从不单独维护，也就不存在除零与舍入分叉。
② 数组按 A(s) 紧凑对齐（长度 30–60，而非全动作空间 2086）， 每次选择是一趟短数组扫描；动作编号经 valid_actions 索引还原。选叶子是最热路径， 这一步把打分工作量压到全动作口径的 1/35–1/70（2086 ÷ 30–60）。

3.1　叶子评估与终局短路

下降到未展开叶子后分两支。若该局面已被规则判终（将死/困毙/和/长将/时钟，§1 篇），直接取终局奖励回填， 不占用网络请求——这一支称为终局短路，越接近残局占比越高；否则把局面转成张量（§1 篇 §5）， 提交推理引擎（§3 篇），以 −vθ 作为叶子回报回填（视角换算见 7.3 节）。

4　瓶颈定量：串行时批从哪来

设并发自弈局数为 G。串行实现里每局每时刻至多 1 个未决请求， GPU 批的期望上限就是 G；而"下降—等待"交替造成请求呈突发状到达， 引擎实际凑到的批远小于 G（第 9 节表 3 首行即此形态）。两点实测给出定量依据：

  • 凑批成本模型（§3 篇式 (1)：前向耗时 tfwd(b) ≈ 1.21 ms + 4.5 µs·b）：批 32 时每局面 42 µs，批 256 时每局面 9.2 µs， 同一张卡吞吐差 4.5 倍；
  • 中间形态带屏障批量（发 K 条 → 全数返回 → 再发下一批）吞吐翻倍，但"等齐"期间本线程不再产出 请求，引擎队列被吃空——实测 GPU 占空比仅 34%。这直接催生第 6 节的无屏障流水线。

5　虚拟损失：让 K 条线"同时存在"

5.1　机制

并发的第一个障碍：两条线在同一次决策中会沿着相同的统计量下降、撞进同一个叶子。 办法是对刚被选定的边临时记一笔假账：

N(s,a) ← N(s,a) + ν 　　,　　W(s,a) ← W(s,a) − ν 　　（在该边结果返回前有效）

式 (1) 的分子分母同时被恶化，该边得分骤降，后续选择自然分流；真实结果返回时沿路径把两笔账 成对撤销（_undo_virtual_loss），统计恢复真实值。

5.2　为什么 W 也要减（而不是只加 N）

若只加 N，当该边经验回报显著优于同侪时，衰减后的得分仍可能全场最高， 第二条线依旧撞车。同时把 W 减 ν，等价于"在它名下记一局假输"， 再优势的边也会被压下去——分流从概率性巧合变成结构性保证。代价是假账期间该边统计暂时失真， 所以必须成对撤销：任何"结果丢失而假账不还"的代码路径都会永久污染统计量。 本框架里撤销与归还写在同一处收割逻辑里（6.1 节伪码），并由测试 5.3-① 对守恒性作回归固定。

5.3　语义等价性与两条不变量

与串行 PUCT 相比，虚拟损失改变的是选择序列（更分散），不改变每条请求的账目： 每条线仍完整经历下降—评估—回填；若干线在途时互相"看不见"对方刚下的子，故同一随机种子下最终访问分布 与串行并非逐位相同——这是并行树搜索的固有性质，AlphaZero 类实现普遍接受。必须恒成立的是两条不变量：

  1. 假账守恒：任意时刻 Σ(未撤销的虚拟损失) = 在飞请求数 ≤ K；
  2. 预算不被跳过烧空：因撞车而撤回的选择不得消耗模拟预算（对应 6.2-① 所述缺陷）。

6　无屏障流水线：收一条、补一条

6.1　结构

带屏障批量（发 K 等 K）在等待期没有新请求进入队列，凑批的请求供给出现空窗。 run_pipelined() 去掉屏障，保持"恒有 ≤K 条在飞"的不变量：

在途表 inflight ← ∅ ;  预算 rem ← n_simulation
while rem > 0 或 inflight ≠ ∅:
    while rem > 0 且 |inflight| < K:
        (leaf, path) ← select() 并落虚拟损失 (2)
        if leaf ∈ inflight:          # 树浅时 K 次选择可能全落同一叶
            撤销 (2) ; break          # 不耗预算，跳出去收割（6.2-①）
        if leaf 已终局:                # 3.1 节短路
            撤销 (2) ; 就地回填 ; rem − 1 ; continue
        提交 leaf 网络输入 → 引擎请求队列
        inflight += 请求 ; rem − 1
    等待"任意一条"完成（信号量许可；超时 300s 则显式报错）
    找一条已完成者：撤销 (2) → 真实结果回填 → inflight − 1

6.2　两个正确性细节（各对应一起真实故障）

  • ① 撞车不得烧预算。树浅时 K 次 select 可能全部落回同一未展开叶。早期实现把跳过也计入模拟预算， 48 次模拟被"跳过"耗尽、根节点尚未展开即返回，下游 get_pi 拿到空分布直接崩溃。 正解：撤销假账、不扣预算、让出补位循环去收割；树撑开后再继续。
  • ② 收割经信号量而非逐条等待。每条完成释放一个许可（§3 篇 RequestLane），主循环 acquire() 后在在途表里找任意一条已完成者处理——避免"挑着等某一条"造成死等， 乱序完成天然成立。
超时是安全网，不是装饰。若引擎半死（请求有去无回），300s 内无任何完成会抛 TimeoutError，让整条训练链显式失败并进日志；没有它，进程会无声吊死——这种故障在 监控面板上只表现为"stalled"，排查成本极高；该场景由超时路径回归覆盖。

7　策略目标、噪声与视角

7.1　访问数 → 策略分布

搜索产出训练目标与落子分布都用同一映射（实现取 log 域计算，等价于幂归一但避免溢出）：

πτ(a) ∝ N(a)1/τ 　（τ > 0）　;　τ → 0 时退化为 π 集中于 argmaxa N(a)

训练样本的策略目标取 τ = 1（访问数比例即"搜索意见"）；实战落子：开局前 exploration_steps 手恒定 τ=1 促探索， 之后 τ=0.1 近贪心。窗口按棋种局长定制：象棋 30 手、五子棋 12 手（对局常见 20–40 手终局，长窗口等于整局皆随机）；配置键 tau_decay_rate / exploration_steps（现为 1.0=恒定段）。

7.2　根节点狄利克雷噪声

P̃ = ε · ξ + (1 − ε) · P 　,　ξ ~ Dir(α) 　,　α = 0.03 × 361 / |A(s)| 　,　ε = 0.25

只加在根节点且只在自博弈时加（式中的 P 即根节点评估落地时写入的先验字段，噪声直接覆写它）：为"网络暂时不看好、 但值得验证"的着法留一扇旋转门。人机对战与晋升评估不加——需要的是当前最强着法。 α 随合法着法数反比缩放是 [1] 的口径；ε 为配置键 dirichlet。

7.3　视角约定（全框架最容易错的一行账）

  • 值头 vθ(s)：轮走方视角（谁走谁的分）；
  • 边累加 W(s,a)：走进孩子的一方（= 走这步的父节点侧玩家） 视角——因此评估落地时 Rt = −vθ，回填循环里 "本层取反、逐层再取反"使双方视角自然交替；
  • 训练样本的 q：对根局面取 −Wroot/Nroot， 即换回"轮走方"视角的搜索估计。

方向弄反的模型会稳定地学会"帮对手下棋"，而训练 loss 曲线完全正常——这是它可怕的地方。 tests/test_mcts_reward_sign.py 七项沿路径逐层核对这条符号链（附录）。

9.1　测量学

  • 吞吐分母为局面数（一次前向入批 B 个记 B），由引擎每千条打印的统计行聚合（§3 篇 9 节）， 非端侧估算；批统计另存整轮直方图，面板头条取整轮均值、滑动窗口只作尾部指示—— 用滑动窗口当整轮均值曾把 245 误报成 16（已由回归测试覆盖）。
  • 线程数存在实测拐点：24–32 线程 ≈ 47–50k 模拟/秒，64 线程回落到 35.9k——free-threading 下 锁竞争与内存带宽接棒成为瓶颈，故 G=32 为默认。
  • 每次模拟的 CPU 账本随统计输出：选叶子 0.13–0.14ms、等推理 0.28–0.33ms（阶段 3 配置）—— 两者之比用于判断瓶颈迁移（CPU 搜索 vs GPU 推理）。
