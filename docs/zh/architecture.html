摘　要

本篇是系统层参考：先立术语（1 节），再给进程拓扑与其间的契约（2 节）、目录导读（3 节）、 "架构注册表 + 神经网络制"的模型管理（4 节）、环境变量配置面（5 节），最后是两套 HTTP 接口的 完整契约表（6、7 节）与日常运维手册（9 节）。工程原则只有一句：一切重状态都在磁盘上有唯一真源， 一切控制路径都能经 HTTP 完成——训练启停、回滚与模型选择均可经接口完成，无需终端操作。

2　进程拓扑与契约

一个进程族的由来：训练进程的 TrainServer 继承推理引擎（§4 篇 10.2）， 自博弈与 fit 同进程共享权重与仓；服务进程则按会话动态养引擎。所以"训练在跑时打不开对战"不会发生—— 两套引擎实例互不相干，共享的只有磁盘上的 checkpoint。代价是两进程各占显存，常驻引擎多时要错峰（本篇 9 节"GPU 被占满时的对战"行）。

4　模型管理：架构注册表 + 神经网络配置

自 2.1 起，「网络」（profile）即命名模型配置：内置 s/m/l 之外，可在控制台「训练 → 网络配置」以名字自定义规模模板（存 data/profiles.json，名字即数据目录，棋种下拉同步出现；现行现役：m8、mini、mini2）。只允许覆写规模键（通道数 / 残差块 / value 隐层 / SE）；表示层与棋规层的键被白名单拒收——防手滑，也防把"网络"用成"换游戏"。

4.3　经验池（buffer）：棋种级命名、来源元数据与闸门

官方名称经验池（旧称「仓/buffer」）。池只跟棋种挂钩，不按网络分家；池元数据里的 source 只记录"最新内容由哪个网络的第几代产生"这一溯源信息。克隆保护：池是环形覆盖存储，重训会逐步覆写旧样本——资产页「经验池」面板每行提供「⧉ 克隆」，整体复制为自动编号的新池（管理在资产页，训练表单只负责选池）（全量复制而非硬链接，因 save 是原位覆盖写；先落 .tmp- 再更名就位，崩溃不留半个池；训练进行中拒绝克隆），在新池上实验、原始状态保真。两种存在形式：原位 default@<模型>（历史兼容，零迁移），或 data/<Game>/buffers/<name>/ 命名仓——主仓与留出集成对存放，meta.json 记录游戏、 表示版本、容量/已用、source={模型, 代数}（即"最新内容来自谁的第几代"）。 同棋种同表示版本的仓可被任意模型直接引用共享（大模型用小模型的仓热身=选同一个仓名，无复制）； 跨表示版本的仓被启动闸门硬拒。每轮存盘自动回写元数据；注册表即目录现场扫描，不留第二份索引。

8　前端与其它入口

8.1　Web 前端（apps/web，零构建）

  • 对弈页 /：三步开局（棋种→模式→级联选网络/代数），每步超时与每 AI 模拟次数/温度开局前可调（localStorage 记忆）， SVG 棋盘、中文记谱、双胜率条、思考计时、⋯ 菜单（悔棋/认输）、音效、移动端自适应。 核心工程是浏览器端棋规引擎（js/env-chess.js）：与服务端 core/env 的 动作编码逐位对齐，随机对局做快照级对拍——否则前后端对合法着法的判定将出现分歧。 人机模式下，前端即时验证着法合法性，后端专注搜索计算，两侧互不等待。
  • 控制台 /admin：六页签：监控/训练/竞技场/资产/工具/日志（哈希深链 #monitor/#train/…；≤720px 顶栏收进 mini 状态条）；Canvas 手绘图表（缩放平移、图例、 横轴标注），亮暗双主题；无外部依赖、无 CDN。
