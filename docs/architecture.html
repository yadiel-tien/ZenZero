摘　要

本篇是系统层参考：先立术语（1 节），再给进程拓扑与其间的契约（2 节）、目录导读（3 节）、 "架构注册表 + 档位制"的模型管理（4 节）、环境变量配置面（5 节），最后是两套 HTTP 接口的 完整契约表（6、7 节）与日常运维手册（9 节）。工程原则只有一句：一切重状态都在磁盘上有唯一真源， 一切控制路径都能经 HTTP 完成——训练启停、回滚与模型选择均可经接口完成，无需终端操作。

2　进程拓扑与契约

一个进程族的由来：训练进程的 TrainServer 继承推理引擎（§3 篇 10.2）， 自博弈与 fit 同进程共享权重与仓；服务进程则按会话动态养引擎。所以"训练在跑时打不开对战"不会发生—— 两套引擎实例互不相干，共享的只有磁盘上的 checkpoint。代价是两进程各占显存，GPU 档位多时要错峰（本篇 9 节"GPU 被占满时的对战"行）。

4　模型管理：注册表 + 档位制

自 2.1 起，「档位」即命名模型配置：内置 s/m/l 之外，可在控制台「训练 → 模型配置」以名字自定义规模模板（存 data/profiles.json，名字即数据目录，棋种下拉同步出现）。只允许覆写规模键（通道数 / 残差块 / value 隐层 / SE）；表示层与棋规层的键被白名单拒收——防手滑，也防把"档位"用成"换游戏"。

4.1　架构注册表

core/network/network.py   BaseNet：设备适配、加载先落 CPU（checkpoint 跨设备通用）
                          Net（"resnet_v1"）    标准 AlphaZero 双头：Conv stem → N×ResBlock(±SE) → 双头
                          BiGameNet（"bigame_v1"）双游戏：各自 stem + 共享 ResNet 躯干 + 各自头，
                                                  forward 按输入 (通道数, 格数) 自动分路
core/network/registry.py  build(arch, config) / known() / infer_arch(ckpt_config)
新架构：在 archs/ 放一个文件、@register('my_arch_v1')，自动导入生效——引擎与训练侧零改动

checkpoint 文件里存 config（含 arch 名与全部规模键）、权重、optimizer/scheduler 状态与 训练步数。加载按 ckpt 内 config 重建网络，与当前进程档位无关——这是跨档对局（§4 篇 10.2 drill） 和"对弈页选任意代"能成立的根基。

4.2　档位

档位表（参数量实测；m 为历史默认档 = 根目录零迁移）。
档位规模（s 档棋类实测）参数量数据目录定位
s128 通道 × 6 残差块8.06Mdata/<Game>/s/快迭代主力（一夜 50 代，§4 篇 10.3）
m256 × 1524.67Mdata/<Game>/默认档；老 498 在此
l256 × 1929.89Mdata/<Game>/l/天花板实验
  • 档位 preset 只许覆写规模键（通道数/块数/头宽）；in_channels、n_actions、n_cells、 feature_version 属棋规与表示层——preset 若试图覆写直接报错。档位、棋种、表示版本三件事不许互相越权。
  • 同棋种不同档位数据完全隔离（各目录一套 ckpt/buffer/best_index/验证集），但仓跨档通用： 表示一致时可把 s 档 buffer 拷给 m 档热身（实测可直接载入；注意仓质量上限，§4 篇 5 节）。
  • 引擎与目录名：m 档保持历史格式（ChineseChess_498），其余带档前缀 （ChineseChess_s_34，§3 篇 8 节）。

4.3　数据仓实体：命名、元数据与闸门

「仓」从隐藏文件升格为可命名实体：原位 default@<模型>（零迁移），或 data/<Game>/buffers/<name>/ 命名仓——主仓与留出集成对存放，meta.json 记录游戏、 表示版本、容量/已用、source={模型, 代数}（即"最新内容来自谁的第几代"）。 同棋种同表示版本的仓可被任意模型直接引用共享（大模型用小模型的仓热身=选同一个仓名，无复制）； 跨表示版本的仓被启动闸门硬拒。每轮存盘自动回写元数据；注册表即目录现场扫描，不留第二份索引。

4.4　版本管理（四条轴 + 一条发布线）

项目自 2.0.0 起遵循语义化版本。单一事实源在 core/utils/version.py， 展示位置：对弈页设置侧栏、控制台标题徽章（v2.0.0 · git 构建号）、/info 与 /api/admin/health、启动横幅、main.py --version。四条版本轴职责互不重叠：

轴取值示例含义与变更时机
应用版本（semver）2.0.0+e852721 整个软件的发布版本，引擎/前端/控制台不单独编号——同仓同发布，另立版本只会制造兼容矩阵。 主版本=表示/协议级破坏变更或里程碑；次版本=新功能；修订=修复。发布流程：改 version.py → CHANGELOG 条目 → git tag vX.Y.Z → push tag → GitHub Release（附权重等制品）。
表示版本 feature_version1 / 2 棋盘张量布局 epoch，烧进 checkpoint；决定特征转换与网络通道数，跨 epoch 不兼容（§1 篇 §6）。
档位 profiles / m / l 命名模型配置（内置 s/m/l ∪ profiles.json 自定义）；只影响体量与数据目录，不影响兼容性（4.2 节）。
模型代数 iteration34 档位内自博弈世代（checkpoint_N.pt），守擂晋升推进（§4 篇 8 节）。

排查问题请附「应用版本 + 表示版本 + 档位 + 代数」四个值——控制台 meta 行与制品页已一并展示。

6　对战 HTTP 接口（端口 5000）

约定：全部 JSON。state 数组为 §1 篇定义的 (7,10,9) int32；会话令牌 pid 由 setup 发放，60s 无心跳自动回收并释放引擎引用；CORS 全开，前端可另托管。

对战 API 契约（实现 services/inference/play_api.py）。
接口请求体成功响应说明
GET /info—{device, device_note, vram{free,total}}device_note 提示当前是否处于降级（如 GPU 被占满后的 CPU 兜底）
GET /devices—{current, devices:[{…status}]}可用设备清单（探测，不含占用状态）
POST /device{device}{device}在线搬迁全部已加载引擎；失败 400（不可用）/409（搬迁失败已回滚）
POST /models{env_name}{indices, best_index, profile, profiles:{s:…,m:…}}跨档位枚举；profile=最近有产出的档（默认档，按 .pt mtime）
POST /setup{model_id, env_class, profile?}{pid, model_id, profile, device, device_note}开局。model_id=0 → 该档最新；CPU 自动降模拟数保可玩
POST /update{pid, array, action, player_to_move}{win_rate}同步盘面：AI 做树复用（§2 篇 8.1），返回其视角胜率
POST /get_action{pid}{action, win_rate, model_id}AI 落一子（阻塞至搜索完成）
POST /reset{pid}{win_rate}重开：AI 树与状态清空

GET / · /docs/ · /admin—HTML对弈页 / 本文档集 / 管理台；静态资源 /css /js /assets/*

错误约定：参数不合法 400；会话不存在 404；引擎异常 500 带 {error}（含堆栈）。 浏览器端对 4xx/5xx 统一以 toast 提示，对慢响应有每步超时保护（细节以 apps/web/js/api.js 实现为准）。

7　控制台 HTTP 接口（/api/admin/）

读接口免鉴权（内网工具定位），写接口在 ZZ_ADMIN_TOKEN 非空时校验 X-ZZ-Token， 不符 401。页面 GET /admin（亮/暗双主题，自适应系统 + 手动锁定）。

控制台 API 契约（实现 services/admin/routes.py；心跳契约见 §4 篇 9 节，统计口径见 §3 篇 9 节）。
接口要点
GET /snapshot一屏全量：meta（实际在跑的档位与网络规模）、live（心跳权威态：阶段/进度/实时 buffer/瞬时吞吐/gpm…）、hardware（1s 环）、rounds（上一轮 perf 行）、heartbeat 原文、trainer 状态、crashes。判"数据是活的还是缓存"看 live.source 与各 age 字段
GET /series曲线：rounds（按累计轮数的 13 条衍生序列）＋ tb（TensorBoard 标量，跨重启按 step 合并＋抽稀）＋ hw 时间序列
GET /env当前参数 + 建议目标（最新 ckpt 所在 棋种×档位）+ 白名单 knobs
GET /train/statuspid / running / 是否收养 / exit_code / stop_after_round / 日志尾
POST /train/start{game, profile, workers, games_per_round, batch_leaves, max_batch?, device?, buffer?, start_from?} → 按第 5 节环境变量拉起；1.2s 内启动即崩会把 stderr 原样带回；重复启动拒绝
POST /train/stop{mode: kill | interrupt | finish_round, grace?}——语义即 §4 篇 9 节三档表；interrupt 带动态宽限（收尾心跳新鲜则延至 10 分钟，绝不升级杀数据）；对不支持 finish_round 的旧进程，先查心跳 caps 再发信号（防 SIGUSR1 默认动作误杀）
GET /artifactscheckpoint / 日志 / 运行目录 / 仓清单（大小、时间、已用/容量、是否最佳）
POST /artifacts/delete{kind, path, confirm}：白名单 kind∈{checkpoint,log,run,buffer}；拒删当前 best（先回滚再删）；删仓需 confirm:"delete-buffer"
POST /best{iteration}：一键改换守擂者（制品页"设为最强"），回滚坏模型的主路径
GET /logs?path=&tail= · /logs/list · /health任意日志尾读（限 log_dir 内，越界 403）；清单=白名单形态 <模块>/latest.log*|console.log*；体检
GET /buffers · POST /buffers/create 数据仓注册表（目录现场扫描：default@<模型> 原位仓 + 命名仓）与建仓；元数据记录棋种、表示版本、容量/已用、最新内容来自哪个模型的第几代
GET /tasks · POST /tasks/start · /tasks/stop · GET /tasks/log 「任务」页后端：注册表驱动（priskvork 常驻；arena / bench / build_cython 一次性），参数按 schema 白名单校验，once 任务退出码即时回传（exit 0 即成功），输出追加落 logs/<任务名>/console.log（统一格式，历次会话连贯），服务重启按 pid + /proc cmdline 收养

8　前端与其它入口

8.1　Web 前端（apps/web，零构建）

  • 对弈页 /：SVG 棋盘、中文记谱、双胜率条、每步计时、悔棋、音效、移动端自适应。 核心工程是浏览器端棋规引擎（js/env-chess.js）：与服务端 core/env 的 动作编码逐位对齐，随机对局做快照级对拍——否则前后端对合法着法的判定将出现分歧。 人机模式下，前端即时验证着法合法性，后端专注搜索计算，两侧互不等待。
  • 控制台 /admin：监控/训练/制品/日志四页；Canvas 手绘图表（缩放平移、图例、 横轴标注），亮暗双主题；无外部依赖、无 CDN。

9　运维手册

要做路径
开一夜训练/admin → 训练 → 核对棋种/档位/参数 → 启动。监控页看：局/分、均批、KL。关浏览器不影响
收工「等本轮结束」（成果完整）；急用机器「优雅停止」；「立即结束」= kill（会丢当轮，确认框写明丢几局）
终止时机§4 篇第 7 节判据：KL 连续 10 代不降 + Val/value 平台 + 晋升胜率均值 < 54% + 跨代对局 < 60%，四项同时满足方可终止
回滚坏模型制品页「设为最强」，或 POST /api/admin/best {iteration}
GPU 被占满时的对战ZenZero 设计为显式失败不静默：auto 探测失败会降级并在 /info.device_note 与前端标注；如需 GPU 推理请先释放 GPU（本机经换班调度台 baton 协调），或手动 POST /device
新旧模型同台对弈页模型下拉先选种类（档位）再选序号，跨档直接对局
